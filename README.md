This is a clean restart of the importer, **not another v2 patch**. The previous HUD, model cache, token HP reconciliation, and background imports are not included in the production userscript. Old source is retained under src/ for comparison only.

## Automatic character import (v3.1.0)

Enable **Auto-sync: On** once for your imported character. The choice and character ID are kept locally for that Roll20 game. The extension checks for its official D&D 2024 sheet and refreshes the imported data automatically. When the Journal sidebar exposes the matching character entry, the script uses Roll20's own double-click to load that sheet, moves **only that script-opened** dialog offscreen while it reads all the tabs, and then checks for changes periodically. It rejects mismatching character IDs and ambiguous same-name sheets, never moves an existing player-owned dialog, and does not clone Roll20's generic headless iframe (the generic iframe URL does not include a character ID).

If Roll20 hasn't rendered the Journal entry or doesn't open it via the normal browser double-click, auto-sync reports **Waiting for a matching journal entry**. Open Roll20's Journal sidebar once to make it available; in that case you may need to open the sheet once for Roll20 to load it. A player-opened visible sheet is read automatically without clicking Import, but its tabs are not switched behind your back. Quick current-view refreshes merge only observed live values into the previous full snapshot so the collected inventory, spells, and features aren't erased. The offscreen full scan runs no more than once every five minutes; current-view scans roughly every sixteen seconds on a scheduled eight-second poll. **New in 3.1.1:** while Auto-sync is enabled and a matching official sheet iframe or browser popout is mounted, a separate bounded HP-only request runs about every second. It reads visible, labeled current/max/temporary HP inputs without visiting tabs; changed HP values update the saved profile and preserve the inventory/spell catalog. Browser scheduling and iframe response time mean this is a best-effort interval, not a guaranteed sub-second update. If the official HP fields are unmounted, no HP value is fabricated. Turn Auto-sync Off to restore any offscreen dialog.

**v3.1.2 popout fix:** Automatic HP watching and current-view refreshing also work through a registered, official 2024 sheet opened in a separate browser window. The opener/editor bridge recognizes later Vue-loaded character names, prefers the matching popout over an older embedded copy, and drops closed popup references. A manually opened popout is never moved offscreen or switched across its tabs by auto-sync. For a popout, keep the original Roll20 editor window open and enable Tampermonkey on the official advanced-sheets domain in **both windows**. If the browser/extension removes the `window.opener` relationship (for example `noopener`) or blocks script injection, the cross-window bridge cannot communicate; live Floorp validation is still needed. The one-second cadence is best effort, especially for minimized/background windows.\n\nThis is a **browser-dependent, opt-in experimental feature**: its journal-open path is based on public DOM and needs live Floorp verification. No background data is guaranteed if Roll20 does not expose the necessary journal controls. Disable Auto-sync if it interferes with Roll20. The existing Read current tab and Import all tabs buttons remain available.

**v3.1.3 non-HP Auto-sync fix:** Automatic current-view imports now accept a recognized change to a skill, spell slot, resource, attack, spell, inventory item, feature, ability or save even if the currently displayed tab has no HP or other stats mounted. An empty result and mismatching character still fail closed. Updates merge into the prior complete import, preserving off-tab items; same-key entries update, but entries removed from an off-tab or virtualized list are not assumed deleted. Player-owned sheet tabs are never switched by Auto-sync. Current-view checks now use an eight-second scheduler with a twelve-second minimum gate (usually about sixteen seconds); HP remains around one second and script-owned background full-tab scans remain limited to five minutes. Live Floorp validation of non-HP field changes and unattended opening of a fully closed sheet are still required.\n\n## Install and use
Install or update the script from https://raw.githubusercontent.com/newnetmp3/roll20embetterment/main/roll20-embetterment.user.js. Disable duplicate/old scripts and reload Roll20. Open an official D&D 2024 character sheet. The new importer appears at the bottom right of the editor. Refresh the sheet list, choose the visible sheet, then use **Read current tab** or **Import all tabs**. The latter navigates rendered tabs and sub-tabs and restores the original tab selection.

## What the new engine captures
- Labeled form values: current, max and temporary HP, AC, speed, initiative (including decimals), six abilities, modifiers, saving throws, skill bonuses, spell slots, level, proficiency, spell bonuses and other identifiable numeric fields.
- Named spells, attacks, inventory, features, resources and skills when those cards are rendered; spell/card text, casting metadata hints and accessible action labels.
- Raw labeled but unrecognized control values in **Fields**, explicit source information, coverage counts, rejected/hidden counters, scanned tabs and limits in **Diagnostics**.
- A local per-campaign snapshot and downloadable JSON export; missing values are **not** replaced with default stats.

This is a player-triggered, read-only scan. It never writes to Roll20 character values, accesses private application state or fetches data from external servers. The iframe and editor communicate via strict origin-checked postMessage. Hidden/headless frames are not treated as a player's open sheet. Bounded traversal avoids hanging the browser.

## Limits
This v3 baseline intentionally supports the official D&D **2024** sheet first; the old combat wheel and the 2014 sheet adapter will return in separate milestones. Roll20 may virtualize or lazily load cards: only rendered DOM values can be collected. All browser integration still needs a live Floorp test; DOM fixture tests cannot establish that the userscript actually loaded inside Roll20's iframe.
